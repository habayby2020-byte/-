# نظام واجهة Windows 11 Web Edition (RTL)

واجهة تحاكي نظام Windows 11 باللغة العربية والاتجاه من اليمين لليسار (RTL) مع إدارة النوافذ وتطبيقات النظام الأساسية:
- الإعدادات (تخصيص المظهر، الخلفيات، السطوع، الصوت)
- مستكشف الملفات (شجرة المجلدات، إنشاء وحذف الملفات)
- المفكرة (Notepad مع حفظ وتنزيل TXT محلياً)
- الحاسبة القياسية (مع دعم لوحة المفاتيح وسجل العمليات)
- متصفح Microsoft Edge
- قائمة ابدأ الأصلية وشريط المهام ودرج النظام والتقويم

## متطلبات التشغيل:
- Node.js (الإصدار 18 أو أحدث)
- npm أو yarn أو pnpm

## خطوات التشغيل السريع:
```bash
# 1. تثبيت الحزم
npm install

# 2. تشغيل خادم التطوير
npm run dev
```
سيتم تشغيل الواجهة مباشرة على المتصفح عبر الرابط: http://localhost:5173

## طريقة التضمين في مشروع React خارجي:
```tsx
import React from 'react';
import { WindowManagerProvider } from './context/WindowManagerContext';
import App from './App';

export default function MyProject() {
  return (
    <WindowManagerProvider>
      <App />
    </WindowManagerProvider>
  );
}
```

## كيف يوصل هذا التطبيق فعلياً للتلفزيون (ولماذا ما فيه زر Cast من الكود)

في النسخ السابقة كان فيه زر "اتصال بالتلفزيون" مبني بالكود — سواء عبر
`BroadcastChannel` (يشتغل بس بين تبويبين بنفس الجهاز) أو عبر سيرفر
WebSocket محلي برمز PIN. كلا الطريقتين **مو نفس "جوجل كاست الحقيقي"**،
فتم شيلهما من الواجهة الافتراضية. السبب تقني ومهم تعرفه:

- **ما فيه أي JS API تقدر أي صفحة ويب تستدعيه تفتح قائمة Cast/Mirroring
  الحقيقية** (نفسها اللي استخدمتها من الإعدادات بنجاح). هذا الزر يتحكم
  فيه المتصفح/النظام فقط، لأسباب أمان — ولا تطبيق ويب يقدر يحاكيه أو
  يستدعيه تلقائياً من داخل الصفحة.
- الطريقة الوحيدة المجانية 100% (بدون أي تسجيل أو رسوم) اللي تعطيك هذي
  القائمة الحقيقية هي **Screen/Tab Mirroring المدمجة في Android
  وChrome** — هذي تصوّر شاشة جوالك (أو تبويب المتصفح) وتبثها للتلفزيون
  كفيديو حي. هذا بالضبط اللي وصفته: "كل شي يتحمّل بالجوال، والبيانات
  تروح للتلفزيون اللي يعرضها فقط" = Mirroring.
- الطريقة الثانية (التلفاز يفتح الرابط بنفسه ويرسمه بكرت شاشته الخاص،
  صفر تأخير) اسمها تقنياً **Custom Cast Receiver عبر Presentation
  API**، وهذي **تحتاج تسجيل تطبيق استقبال في Google Cast SDK Developer
  Console** (رسوم تسجيل لمرة وحدة، تاريخياً حوالي $5) — ما فيه طريقة
  مجانية توصل لنفس هذا السلوك لتطبيق تفاعلي مخصص زي هذا. مستقبل
  الوسائط المجاني (Default Media Receiver) **يشتغل بس لتشغيل
  فيديو/صورة/صوت، ما يقدر يعرض تطبيق ويب تفاعلي فيه مؤشر وكيبورد.**

### الحل العملي المطبّق الحين
التطبيق مصمم يشتغل بالكامل من جهاز واحد (جوالك)، وتعرضه على التلفزيون
بنفس ميزة الـ Mirroring الحقيقية المجانية:

1. افتح `http://localhost:4000` (أو رابط النشر) على جوالك — هذي هي
   الواجهة نفسها (سطح المكتب التفاعلي)، ما فيه صفحتين منفصلتين للجوال
   والتلفاز بعد الآن.
2. تتحكم فيها مباشرة بلمس الأيقونات، أو تفعّل زر "وضع اللمس" أسفل يسار
   الشاشة للتحكم بمؤشر عن بعد وأنت تراقب التلفزيون بدل جوالك.
3. من Chrome: القائمة ⋮ ← Cast... واختر تلفازك. أو من الجوال: الإعدادات
   السريعة ← Cast/Smart View واختر تلفازك. زر "عرض على التلفزيون" أسفل
   يمين الشاشة يشرح نفس الخطوتين داخل التطبيق.
4. من هذي اللحظة التلفزيون يعرض نفس شاشة جوالك حي — بدون أي كود من هذا
   المشروع يتدخل، وبدون أي رمز أو تسجيل.

### ميزة متقدمة اختيارية (جهازين فعليين على نفس الشبكة)
لو عندك فعلاً جهازين (مثلاً لابتوب يعرض الشاشة + جوال يتحكم)، فيه وضع
تحكم بعيد عبر WebSocket محلي بدون رمز، مبني مسبقاً وجاهز:
- افتح `http://<IP>:4000` على الجهاز اللي بيعرض — يستقبل تلقائياً بصمت.
- افتح `http://<IP>:4000/?mode=remote-controller` على الجوال اللي
  بيتحكم، واضغط "اتصال بالتلفزيون" — يرتبط تلقائياً بأول جهاز عرض
  مفتوح على نفس السيرفر، بدون رمز.
- يحتاج `npm start` (سيرفر `server.js` شغّال فعلياً، أو `npm run dev`)
  ويشتغل فقط بين جهازين فعليين على نفس الشبكة المحلية — هذي إضافة
  منفصلة لمن يحتاجها، مو بديل لميزة الـ Cast الحقيقية.

## إضافة أي ملف كتطبيق جديد بدون كتابة كود

اسحب أي ملف (صورة، فيديو، صوت، PDF، نص، أو HTML جاهز) وأفلته فوق
`إضافة-تطبيق.bat` في جذر المشروع — أو حط أي عدد من الملفات داخل مجلد
`apps-inbox/` وشغّل `إضافة-تطبيق.bat` بدبل كليك عادي. السكربت
(`tools/Add-App.ps1`) يصنع تلقائياً مجلد تحت `apps/` فيه `index.html`
مناسب لنوع الملف و`manifest.json` باسم التطبيق، فيظهر فوراً على سطح
المكتب وقائمة ابدأ بمجرد ما يكون السيرفر شغّال (`npm start` أو
`npm run dev`) — نفس آلية `apps/` الموجودة أصلاً، بدون أي إعادة بناء
ولا تعديل كود.

## تغليف الجوال كتطبيق APK (بدل متصفح)

عشان يصير تطبيق APK له أيقونة وصلاحيات خاصة (مو تبويب متصفح)، أسهل طريقة
هي Capacitor — يغلّف نفس الصفحة بمحرك WebView أصلي ويوجّهها مباشرة على
عنوان السيرفر:

```bash
npm install @capacitor/core @capacitor/android
npx cap init "سطح المكتب" "com.example.windesktop"
```

وفي `capacitor.config.ts` وجّه السيرفر مباشرة بدل تضمين ملفات ثابتة:
```ts
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'com.example.windesktop',
  appName: 'سطح المكتب',
  // عنوان سيرفرك على الشبكة المحلية أو رابط النشر — غيّره لعنوانك الفعلي.
  server: {
    url: 'http://192.168.1.50:4000',
    cleartext: true, // لو العنوان http محلي وليس https
  },
};

export default config;
```

ثم:
```bash
npx cap add android
npx cap sync
npx cap open android   # يفتح Android Studio لبناء الـ APK
```

هذي الطريقة تعطيك تطبيق حقيقي بأيقونة خاصة وصلاحيات شبكة محلية
(`INTERNET`, `ACCESS_NETWORK_STATE` تُضاف تلقائياً من Capacitor). داخل
التطبيق، زر "عرض على التلفزيون" يفتح نفس إرشادات Mirroring الحقيقية —
Android تعرض قائمة Cast الحقيقية لأي تطبيق مفتوح على الشاشة، تطبيق ويب
أو تطبيق أصلي، فما فيه فرق هنا. بناء ملف الـ APK نفسه يحتاج Android
Studio/Gradle على جهازك — ما أقدر أبنيه من هذا المحادثة لأن بيئة
التنفيذ هنا بدون اتصال إنترنت وبدون أدوات أندرويد. الكود أعلاه كافي
لأي شخص عنده Android Studio يبني الـ APK مباشرة بدون أي تعديل إضافي.
