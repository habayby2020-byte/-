# MiracastPresentationPlugin

طريق الاتصال **الوحيد** بين الجوال والتلفزيون بهذا المشروع. يستخدم
API أندرويد الأصلي (`DisplayManager` + `Presentation`) المبني تحديداً
لهذا النوع من الأجهزة (Wireless Display / Miracast) — نفس القائمة
اللي تلقاها بإعدادات الاتصال وتسميها أندرويد "Cast" (بدون أي علاقة
بحساب جوجل أو Google Cast SDK).

## ليش هذا الطريق، ومو غيره؟

- **مضمون على جهازك تحديداً** — تأكدت بالفحص (إعدادات > Cast) إن كل
  تلفزيوناتك تظهر وتشتغل فعلياً. هذا عكس Google Cast الرسمي اللي
  يحتاج تلفزيون مسجّل كـ"مستقبل" (Chromecast/Android TV)، وعكس
  الحلول اللي تعتمد على متصفح التلفزيون (ما فيها متصفح إطلاقاً هنا —
  التلفزيون يستقبل بث Miracast فقط).
- **بدون شبكة إطلاقاً بين الجهازين بعد الاتصال** — بعد ما يرتبط
  Miracast، التطبيق ينشئ نافذة `Presentation` على الشاشة الثانية
  ويحقن أوامر التحكم فيها بجافاسكربت مباشر (`evaluateJavascript`)،
  صفر WebSocket، صفر PIN، صفر اعتماد على شبكة واي فاي مشتركة بين
  التطبيقين (Miracast نفسه هو طبقة النقل).
- **مسار واحد بدون تشتت** — هذا بديل كامل لكل الطرق الثانية اللي
  كانت بالمشروع (Google Cast SDK، جسر شبكة محلي NSD، W3C Presentation
  API، PhoneHostBridge). كلها انحذفت.

## كيف يشتغل بالتفصيل

1. المستخدم يضغط زر "اتصال" بالتطبيق → `openCastSettings()` يفتح
   شاشة إعدادات أندرويد (يجرب `CAST_SETTINGS` ثم `WIFI_DISPLAY_SETTINGS`
   ثم `WFD_SETTINGS` بالترتيب، أول واحد يشتغل يوقف).
2. يختار التلفزيون من القائمة (نفس تجربتك المعتادة بالضبط).
3. بمجرد الاتصال، أندرويد يطلّع "شاشة ثانية" (`Display`) فيها علم
   `FLAG_PRESENTATION` — الـ plugin يلتقطها تلقائياً عبر
   `DisplayManager.DisplayListener`، بدون أي زر ثاني ولا أي كود يدوي
   من المستخدم.
4. الـ plugin يفتح `Presentation` فيها `WebView` يحمّل **نفس** حزمة
   التطبيق المبنية (نفس الرابط اللي شغّال فيه تطبيق الجوال، مأخوذ من
   `getBridge().getWebView().getUrl()`) بس بإضافة `#tv` — فيتوقف
   انعكاس الشاشة الخام (اللي أندرويد يسويه تلقائياً كسلوك افتراضي)
   ويبدأ عرض واجهة سطح المكتب الفعلية (`WindowsDesktopContainer`).
5. بما إن صفحة الجوال (بدون `#tv`) تفتح `ControllerApp` تلقائياً
   (شوف `src/App.tsx`)، الجوال يتحول للوحة تحكم بنفس اللحظة — بدون
   أي تنسيق إضافي.
6. كل أمر تحكم (حركة ماوس، نقرة، كتابة...) يرسله الجوال عبر
   `sendCommand()`، والـ plugin يحقنه مباشرة بـ
   `window.onTvControllerInput(cmd)` داخل WebView التلفزيون.

## التثبيت

يُنسخ تلقائياً ضمن بناء GitHub Actions (`build-apk.yml`) — نفس أسلوب
الإضافات الأصلية الثانية بالمشروع: الملف ينسخ لمسار الحزمة الصحيح،
ويُسجَّل في `MainActivity.java` بسطر واحد:

```java
registerPlugin(MiracastPresentationPlugin.class);
```

ما يحتاج أي صلاحية خاصة بـ `AndroidManifest.xml` — `DisplayManager`
API عام بدون صلاحيات، وMiracast نفسه يديره نظام التشغيل. يحتاج فقط
مكتبة `androidx.webkit:webkit` (يضيفها الـ workflow تلقائياً) عشان
يقدر يخدّم ملفات التطبيق لـ WebView التلفزيون بنفس أسلوب Capacitor
الداخلي (`WebViewAssetLoader`) — هذا بالضبط اللي يحل مشكلة "الشاشة
البيضاء".
